# 아이디어 구상 중 — 안전문서 기반 맞춤 시험 (2026-07-31)

> 상태: **구상 단계. 팀 합의 전.** 확정되면 PLAN.md 를 갱신한다.
> 배경: "지금 구성이 메리트가 없다"는 팀 내 의견 → 차별점을 만드는 방향 전환 검토.

## 한 줄 요약

관리자가 **자기 사업장의 안전 문서**를 넣으면 → AI가 그 문서로 **문제·채점기준·정답 초안**을 만들고 → 관리자가 승인하면 → 응시자가 그 맞춤 시험을 보고 채점받는다.

## 고객이 둘이 된다

| 고객 | 하는 일 | 얻는 것 |
|---|---|---|
| **관리자** (사업주·안전관리자) | 안전 문서 업로드 → 생성된 문제 확인·승인 | 우리 사업장 맞춤 시험. 외국인 노동자 안전교육 의무 이행 |
| **응시자** (외국인 노동자) | 그 시험 응시 | 실제 자기 일터 문서로 배우고 평가받음 |

## 왜 메리트가 되나

1. "미니 TOPIK이랑 뭐가 달라?" → **"당신 공장 문서로 만드는 시험은 우리뿐"**
2. 기존 채점 파이프라인 **100% 재사용** — 채점기는 문항 출처를 안 따진다. checklist 만 있으면 채점된다
3. 인용 검증 기술을 생성 쪽에 뒤집어 쓴다 — **"문서에 없는 문제는 자동 폐기"**. 남들 RAG 데모와 갈리는 지점
4. 백엔드가 이미 만든 객관식 모델(choices·correctAnswer)이 이 그림에 정확히 맞는다

## 지켜야 할 원칙 (이거 깨지면 시험이 아니다)

1. **생성은 시험 전 + 관리자 승인 필수.** 응시자마다 실시간 생성 금지 — 같은 사업장 응시자는 같은 문제를 봐야 공정하고 재현된다. AI 생성물은 어디까지나 '초안'이고 승인이 '확정'이다.
2. **모든 생성물에 문서 인용 근거.** 문제·정답·체크리스트마다 "문서 어느 문장에서 나왔는지"를 붙이고, 인용이 실제 문서에 있는지 코드로 검증한다(citation.py 방식 재사용).

## 흐름 그림

```
[관리자]
  안전 문서 업로드 (PDF/텍스트)
    ↓
  AI 생성: 문항 + 체크리스트 + (객관식이면) 정답   ← 전부 문서 인용 달림
    ↓
  인용 검증: 문서에 없는 내용으로 만든 문항 자동 폐기
    ↓
  관리자 확인·승인  ← 여기서 '초안'이 '확정 문항'이 됨
    ↓
  DB 등록 (기존 items 형식 그대로)

[응시자]
  기존 흐름 그대로: 시험 → /score → /finalize
```

## 파트별 영향

| 파트 | 새로 할 일 | 크기 |
|---|---|---|
| 우리 (채점+문항) | 문서→문항 생성 모듈 (기존 llm/·citation 재사용) | 중 |
| 백엔드 | 문서 업로드 저장, 생성 요청 API, 승인 상태 관리 | 중 |
| 프론트 | 관리자 화면 (업로드·문제 확인·승인) | **대** |
| 채점 파이프라인 | **변경 없음** | 0 |

## 말하기 = 문서 속 이미지 문항 (7/31 추가)

말하기는 **안전문서 안의 이미지**(예: 비상구 위치 지도)를 보고 말로 답하는 방식.
기획서의 원래 말하기 유형(사진 설명)을 "그 사업장 문서 속 이미지"로 강화한 것이다.

**핵심 설계: 정답은 생성 시점에 체크리스트 안에 박는다.**
- 생성 때만 AI가 이미지를 읽는다 → "비상구 위치(왼쪽 복도 끝)를 말했는가"처럼 정답이 든 체크리스트를 만든다
- 채점 때는 이미지가 필요 없다 → 음성→글자→체크리스트 판정, **기존 파이프라인 무변경**

**이미지 소싱 원칙 (7/31 결정): 파싱이 기본, 생성은 사실상 금지.**

> 판단 기준: **이미지가 '사실'을 담으면 파싱만, '상황'을 담으면 제작 가능.**

| 이미지 종류 | 예 | 방식 |
|---|---|---|
| 사실 이미지 (틀리면 위험) | 비상구 지도, 설비 배치도, 대피 경로 | **문서에서 파싱만.** 원본 그대로, 보정·재생성 금지 |
| 상황 이미지 (예시 장면) | 안전모 미착용, 지게차 주변 보행 | 디자이너(양은희) 제작 삽화 우선. AI 생성보다 품질 균일·리스크 0 |

이유: AI가 그린 비상구 지도는 실제 공장과 다르다. 그 그림으로 시험 보면 응시자가
**틀린 안전 정보를 학습**한다 — 안전 시험이 안전을 해치는 역설. 파싱은 PDF에서
이미지+주변 캡션 추출(표준 기술)이며, 캡션은 정답 교차 검증 재료로도 쓴다.

**이미지 없는 문서도 문제없다** — 말하기가 반드시 이미지형일 필요가 없다:
- 이미지 있음 → 사진 설명형 ("이 지도에서 비상구 위치를 말하세요")
- 텍스트뿐 → 재진술형 ("소화기 사용 순서를 말해보세요") / 상황 대화형 ("기름 유출을 발견했습니다. 보고하세요")
- "어떤 형태의 안전문서든 시험으로 바꾼다"가 오히려 강점 설명이 된다.

이미지 문항 전용 리스크:
- **AI가 그림을 잘못 읽으면 틀린 정답이 시험 기준이 된다** (지도 독해는 텍스트보다 오류율 높음) → 관리자 승인 화면에서 이미지+생성 정답을 나란히 보여주고 확인받는 것이 유일한 방어선
- **인용 검증이 이미지에는 안 통한다** (그림 내용을 코드로 대조할 수 없음) → 이미지 주변 텍스트(범례·설명)와 교차 확인, 없으면 "승인 필수" 등급으로 분류
- 말하기는 여전히 STT 전제 (Azure 미정이면 Whisper 경로), 이미지 표시·승인 화면은 프론트 부담 추가

## 리스크

- 일정: 8/10 쓰기 완성 계획 위에 얹힘. 프론트 부담이 특히 큼 → **팀 합의 필수**
- 정체성: 안전 '지식' 시험으로 오해될 수 있음 → 방어: 내용은 문서에서 오되 채점은 여전히 언어 사용 중심(55%). 우리는 한국어 시험이고 소재가 맞춤형인 것
- 문서 품질: 관리자가 넣는 문서가 엉망이면 문제도 엉망 → 승인 단계가 방어선

## 안전문서 데이터 출처 (7/31 조사)

| 용도 | 출처 | 비고 |
|---|---|---|
| 개발·테스트 | **KOSHA(안전보건공단) 통합자료실** — 외국인근로자 카테고리, 16개 언어 교육자료, OPS(한장짜리 안전수칙) | 공공누리(출처 표시 시 자유 이용). OPS가 생성 테스트에 적당한 크기 |
| 시연 | **가상 공장 문서 자작** ("(주)K-테스트 식품공장 안전수칙") — 내용은 KOSHA 기반, 배치도는 디자이너 제작 | 가상 공장이라 "AI가 지도 잘못 읽음" 문제 소멸, 기밀·저작권 리스크 0 |
| 이미지 | KOSHA 포스터·OPS 일러스트 + 디자이너 제작 배치도 | 사실 이미지(지도류)는 자작만 |

발표 논리: KOSHA가 16개 언어 자료를 만들 만큼 국가가 돈 쓰는 문제인데,
**"그 자료로 시험을 만들어 이해를 확인해 주는 서비스는 없다. 그게 우리다."**
