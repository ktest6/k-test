체크리스트로 채점하면 더 잘 맞을까

AI Hub 외국인 말하기 답안 281건에 채점 방식 네 가지를 똑같이 돌려, 사람 채점자 점수와 얼마나 맞는지(QWK)와 같은 답안을 세 번 채점해도 같은 점수가 나오는지(재현성)를 쟀다.

날짜 2026-08-09 표본 답안 281건 · 문항 9종 · 화자 270명 사람 점수 AI Hub 전문 평가자 0~5 모델 gemini-3.1-flash-lite · 온도 0 LLM 호출 1,383회

한 줄 결론

이번 시험지에서는 LLM 이 점수를 직접 매기는 쪽이 이겼다. 체크리스트로 쪼개 채점하니 사람 점수와의 일치도가 0.79 → 0.51 로 떨어졌고, 문항별로 항목 비중을 학습시키자 그 손해를 절반쯤 되찾았다(0.62). 다만 진 이유가 ‘체크리스트라서’가 아니라 ‘항목이 문항당 2개뿐이라서’라는 것도 함께 나왔다 — 항목 2개가 담을 수 있는 정보의 천장 자체가 0.69 였다.

그래서 논문(RLCF) 방식으로 항목을 다시 뽑아 2차 실험을 했다. 항목이 2개 → 6개로 늘자 정보 천장이 0.69 → 0.80 로 올랐고, 그 값을 실제로 받아 간 것은 가중치 학습 하나뿐이었다(0.70 — 1차의 같은 방식 0.62 를 유의하게 이김). 그래도 LLM 직접 채점(0.79)은 못 이겼다.

무엇을 비교했나

바뀌는 것은 오직 ‘점수를 만드는 방법’

비교가 성립하려면 달라지는 것이 하나여야 한다. 그래서 모델·온도·읽는 글자를 전부 똑같이 두고 점수를 만드는 방법만 바꿨다. 입력은 음성이 아니라 사람이 직접 적은 전사를 썼다 — 받아쓰기 기계를 끼우면 채점 방식의 차이인지 그날 받아쓰기 운인지 구분할 수 없기 때문이다.

A0 · 학습 안 씀

LLM 이 바로 점수

문항과 답안을 주고 0~5 점을 매기게 한다. 근거 인용도 함께 받는다.

A1 · 예시 사용

LLM 이 바로 점수 (퓨샷)

A0 과 같되 같은 문항의 학습 겹에서 뽑은 채점 예시 4~6 개를 함께 보여 준다.

B · 학습 안 씀

체크리스트 충족율

문항마다 체크리스트를 미리 만들어 고정하고, 항목마다 O/X 로 판정해 충족율 × 5 를 점수로 삼는다.

C · 가중치 학습

체크리스트 + 문항별 가중치

B 의 O/X 를 그대로 재사용해 “어느 항목이 더 중요한가”를 사람 점수에서 배운다. LLM 추가 호출 0 회.

B 와 C 는 완전히 같은 O/X 판정을 쓴다. 둘의 차이는 O/X 를 점수로 바꾸는 방법뿐이라, “가중치 학습이 무엇을 벌었는가”가 깨끗하게 분리된다.

공정하게 재기

못 박아 둔 네 가지

  • 같은 시험 겹 — A1·C 는 학습 데이터를 쓰고 A0·B 는 안 쓴다. 그래서 네 방식 모두 화자(speaker_id) 단위 5겹의 시험 겹 예측만 모아 채점했다. 같은 사람이 배우는 쪽과 시험 보는 쪽에 동시에 들어간 경우 0명.
  • 사람 점수 — AI Hub 전문 평가자의 내용 점수 0~5. 분포 0점 18건 · 1점 20건 · 2점 62건 · 3점 96건 · 4점 74건 · 5점 11건.
  • 신뢰구간 — 화자를 통째로 다시 뽑는 부트스트랩 1,000 회. 구간이 0 을 걸치면 “좋아졌다”고 쓰지 않는다.
  • 제외 — 한 방식에서라도 점수를 못 낸 답안은 모든 방식에서 뺀다. 최종 제외 0건.

해석

왜 체크리스트가 졌나 — 기준선 세 개로 읽기

QWK 0.51 이 나쁜 값인지 아닌지는 혼자서는 알 수 없다. 그래서 같은 표본·같은 겹으로 잣대 세 개를 세웠다.

  • 바닥선 0.00 — 답안을 아예 읽지 않고 평균 점수만 답하기.
  • 길이 기준선 0.64 — 답안의 글자 수 하나만 보고 맞히기. 충족율(B)은 이 잣대에 졌다(+0.127). 가중치를 배운 C 도 길이와 비긴다(구간이 0 을 걸침).
  • 정보 천장 0.69 — 충족 개수(0·1·2)를 정답을 다 보고 가장 유리하게 점수로 바꾼 값. C 는 이 천장에서 0.075 밖에 떨어져 있지 않다.
즉 병목은 결합 방식이 아니라 체크리스트 항목 자체다. 결합을 아무리 잘해도 항목이 2 개인 한 0.69 를 넘을 수 없는데, LLM 직접 채점은 이미 0.79 다. 8/6 계단 5 실험에서 “병목은 결합층이 아니라 자질”이라고 나온 것과 같은 모양이다.

항목이 2 개가 된 것은 프롬프트 잘못이 아니다

팀원 프롬프트는 “억지로 개수를 채우지 말라”고 지시하고 있고, AI Hub 문항이 실제로 “보통 어디에서 쇼핑하세요? 왜 그곳에서 쇼핑하세요?”처럼 요구가 두 개다. 프롬프트는 지시대로 동작했고, 시험지가 얕았다. 우리 K-TEST 직무 문항은 요구가 3~5 개라 천장이 달라질 수 있다.

덤으로 나온 것

근거 없이 점수를 주는 비율

A0·A1 은 LLM 이 점수를 정하므로, 인용이 원문에 없어도 점수가 나간다. 실측 결과 인용이 원문과 맞은 비율은 A0 98.6% · A1 99.3% 였다. 즉 100 건 중 1 건 안팎은 근거 없이 점수를 준다. B 는 규약상 인용이 원문에 없으면 그 항목을 미충족으로 내리므로(폐기 10건) 그런 점수가 원리적으로 나오지 않는다. 점수 정확도만 보면 A 계열이 이기지만, “왜 이 점수인가”를 답할 수 있는 쪽은 체크리스트다.

후속 실험 (같은 날)

논문 방식으로 항목을 늘려 봤다

1차 실험의 진단은 “항목이 2 개뿐이라 천장이 낮다”였다. 그래서 논문 RLCF(Checklists Are Better Than Reward Models, Apple·CMU, 2025)의 체크리스트 생성법을 그대로 이식했다. 논문의 핵심은 지시문만 보고 항목을 뽑지 말라는 것이다 — ① 품질이 서로 다른 후보 답안을 먼저 만들고 ② 그것들이 실패하는 방식을 전부 적어 항목으로 삼으며 ③ 항목마다 중요도 0~100 을 붙인다. 논문 실측으로 이 방식이 원자성 68→90, 포괄성 74→82 로 앞선다.

우리 조건에 맞춘 것 두 가지. 후보 답안은 실제 응시자 답안을 절대 쓰지 않고 지시문만 보고 지어냈다(시험지 오염 방지). 그리고 논문이 붙이는 보편 항목 2 개(직접 답했는가 · 상황에 맞는 말투인가)를 우리 말하기 시험 말로 옮겨 붙였다.

결과: 항목이 문항당 2 개 → 과제 항목 4개 + 보편 항목 2개 = 6개로 늘었다(9 문항 전부 같음). 상한을 10 개로 열어 뒀는데도 4 개에서 멈춘 것은, 이 문항들이 실제로 요구하는 것이 그만큼이기 때문이다.

실제로 나온 체크리스트 — “보통 어디에서 쇼핑하세요? 왜 그곳에서 쇼핑하세요?” (앞의 숫자가 LLM 이 매긴 중요도 0~100)

  1. 100 · 주로 쇼핑하는 장소를 구체적으로 언급했는가?
  2. 100 · 해당 장소에서 쇼핑하는 이유를 설명했는가?
  3. 70 · 질문 내용과 직접적인 관련이 없는 불필요한 정보를 배제했는가?
  4. 50 · 이유에 대해 구체적인 근거를 들어 답변을 확장했는가?
  5. 50 · 요청받은 것에 직접 답했고, 주제를 벗어난 내용으로 답안을 채우지 않았는가? 보편
  6. 50 · 상황과 듣는 사람에 맞는 말투·격식으로 말했는가? 보편

왜 논문 장치가 안 먹었나

0~100 채점이 사실은 세 칸이었다

항목 점수 1,686칸을 열어 보니 99% 가 0 · 50 · 100 세 값이었다. 논문은 항목마다 25 번 뽑아 평균을 내서 부드러운 점수를 만드는데, 우리는 재현성 규칙 때문에 온도 0 · 1 회 호출이라 평균 낼 것이 없다. 0~100 이 이진보다 나을 이유가 사라진 것이고, 그 잡음 섞인 값으로 학습한 H(0.596)가 이진으로 학습한 F(0.698)에 유의하게 진 것이 그 대가다.

중요도 가중이 안 먹은 이유도 같은 결이다 — 과제 항목 4 개 중 2 개가 중요도 100 으로 몰려서 가중치의 실질 차이가 작았다. 중요도를 LLM 이 짐작해 주는 것보다, 데이터에서 배우는 쪽이 확실히 낫다는 것이 이번 대조의 결론이다.

부수 발견 — 부정형 항목은 우리 인용 규약과 부딪힌다. “~을 배제했는가”, “~을 늘어놓지 않았는가” 같은 항목은 없는 것을 원문에서 인용할 수 없어 무더기로 폐기됐다(이진 40건 · 점수 79건). 다음 생성 프롬프트에서는 부정형 항목을 금지해야 한다.

재현성은 이번에도 우열을 못 가렸다. 이진·0~100 두 패스 모두 3 회가 소수점까지 같았고 항목 칸 변동은 이진 0/360, 점수 0/360 이다. “칸이 많아지면 더 흔들릴 것”이라는 예상이 빗나갔다 — 흔들린 것이 아니라 애초에 세 칸만 쓰고 있었다.

정직하게

논문과 우리 조건의 차이

아래 차이가 있으므로, 이 결과는 “논문 방식이 틀렸다”가 아니라 “우리 조건에서는 이렇게 나왔다”로 읽어야 한다.

  • 논문의 flexible scoring 은 항목마다 25회 샘플링해 평균을 쓴다. 우리는 온도 0 · 1회 호출이라 '한 번 뽑은 값'이며, 25회 평균이 주는 부드러운 점수의 이점은 여기서 재현되지 않는다.
  • 논문의 체크리스트 생성 모델은 Qwen2.5-72B 급이고, 우리는 판정과 같은 gemini-3.1-flash-lite 다(생성과 판정에 같은 모델을 쓰는 것도 논문과 다르다).
  • 논문은 영어 지시-따르기 과제이고, 우리는 한국어 말하기 시험 문항 9종이다. 우리 문항은 요구 사항이 대체로 둘(정보 + 이유·묘사)이라 애초에 항목이 적게 나온다.
  • 논문은 후보 응답으로 실제 모델 출력을 쓴다. 우리는 시험지 오염을 막으려고 실제 응시자 답안을 절대 쓰지 않고 지시문만 보고 지어낸 가상 답안 4개를 쓴다.
  • 논문의 보편 항목 2개는 중요도 합 100 이고 그 배분은 생성 모델이 정한다. 우리는 문항마다 값이 달라지지 않도록 50/50 으로 고정했다.
  • 논문의 목적은 강화학습 보상 신호이고, 우리 목적은 사람 채점과의 등급 일치(QWK)다. 같은 체크리스트라도 재는 자가 다르다.

그래서 다음

제안 다섯 가지

  1. 부정형 항목을 금지하고 한 번 더. 폐기된 항목이 이진 40 건·점수 79 건이다. 이것만 고쳐도 F 가 더 오를 여지가 있다 (지금은 폐기가 곧 미충족이라 없는 점수를 깎고 있다).
  2. 같은 실험을 우리 문항으로. 이번 결론의 한계는 시험지에 있다. AI Hub 문항은 요구가 둘뿐이라 항목이 4 개에서 멈췄다. 요구가 3~5 개인 직무 문항이면 천장이 더 올라갈 수 있다 — 천장이 오르면 F 도 따라 오른다는 것을 이번에 확인했다.
  3. 둘 중 하나가 아니라 둘 다 넣기. LLM 직접 점수와 체크리스트 항목 O/X 를 함께 자질로 넣어 결합 모델(계단 5)을 학습시킨다. 지금 최고(A1 0.787)와 v2 천장(0.797)이 비슷한 높이라, 남은 이득은 두 신호를 합칠 때 나온다.
  4. 체크리스트를 점수용이 아니라 근거·피드백용으로. “무엇이 빠졌는지”를 응시자에게 돌려주는 값은 LLM 점수에는 없다. 점수는 A 계열, 설명은 체크리스트로 나누는 구성이 가능하다.
  5. 모델을 바꿔 순위가 유지되는지 확인. 지금은 판정 모델이 한 종류뿐이라, 이 순위가 모델 특성인지 방식 특성인지 가릴 수 없다. 논문의 25 회 샘플 평균을 흉내 내려면 온도를 올려야 하는데, 그러면 재현성을 잃는다 — 그 맞바꿈도 함께 재야 한다.

정직하게

이 결과로 말할 수 없는 것

  • 문항당 답안이 27~40건뿐이다. C 는 문항마다 항목 2.0개짜리 가중치를 이 표본으로 배운다 — 표본이 작아 배운 비중 자체가 흔들릴 수 있다.
  • 겹 하나에 문항당 5~8건만 들어가므로 QWK 가 표본 구성에 민감하다. 그래서 점 추정치보다 신뢰구간을 먼저 봐야 한다.
  • AI Hub 데이터는 우리 시험(직무 한국어)과 과제 성격이 다르다. 여기서 이긴 방식이 우리 문항에서도 이긴다는 보장은 없다.
  • AI Hub 의 실제 채점 기준표는 공개돼 있지 않아 A0·A1 의 기준 설명은 우리가 썼다. 세 방식이 같은 조건이라 비교는 성립하지만, 절대 점수의 높낮이는 기준 문구에 좌우된다.
  • 사람 점수 자체의 채점자 간 일치도(인간-인간 QWK)를 이 데이터로는 잴 수 없다(답안마다 평가자가 한 명이다). 그래서 '사람 수준에 도달했다'는 말은 할 수 없다.
  • 판정 모델은 gemini-3.1-flash-lite 하나뿐이다. 다른 모델에서도 같은 순위가 나올지는 안 쟀다.

쉬운 말 사전

QWK (이차 가중 카파)
사람 채점자와 기계의 점수가 얼마나 겹치는지 재는 자. 1.0 이면 완전 일치, 0 이면 아무렇게나 찍은 것과 같다. 한 칸 차이보다 세 칸 차이를 훨씬 크게 벌한다.
시험 겹 (out-of-fold)
배울 때 쓴 답안으로 시험을 보면 점수가 부풀려진다. 그래서 답안을 다섯 묶음으로 갈라, 네 묶음으로 배우고 남은 한 묶음에서만 점수를 낸다. 사람 단위로 갈라서 같은 화자가 양쪽에 동시에 들어가지 않게 했다.
95% 신뢰구간 · 부트스트랩
표본을 다시 뽑아 계산을 1,000 번 반복해, 이 숫자가 표본이 조금 달랐어도 버틸지를 본다. 두 방식의 차이 구간이 0 을 포함하면 “차이가 있다”고 말하지 않는다.
퓨샷 (few-shot)
채점 예시 몇 개를 함께 보여 주고 매기게 하는 방식. 예시는 반드시 배우는 쪽 묶음에서만 뽑는다.
문항별 가중치 학습
같은 체크리스트라도 문항마다 중요한 항목이 다르다. “이 문항에서는 이유 설명이 장소 언급보다 세 배 중요하다” 같은 비중을 사람 점수에서 배우는 것. RocketEval 이 쓴 방식이다.
정보 천장
정답을 다 보고 가장 유리하게 맞췄을 때의 점수. 실제로는 쓸 수 없지만, “이 재료로는 여기까지가 최대”를 알려 준다.

다시 돌리려면

재현 방법

cd assessment/scripts/checklist_lab
python gen_checklists.py            # 문항별 체크리스트 생성(1회, 고정본)
python run_experiment.py            # A0·A1·B 판정 (중간에 끊겨도 이어서 함)
python run_experiment.py --repro --pass-tag rep1   # 재현성 1·2·3 회차
python analyze.py                   # QWK·신뢰구간·재현성
python extra_baselines.py           # 바닥선·길이 기준선·정보 천장
python make_report.py               # 이 보고서

모든 수치의 원본은 assessment/outputs/checklist_lab/results_summary.json 에 있다. 채점 서버 코드(assessment/src/)는 이 실험에서 한 줄도 바뀌지 않았다(테스트 292 개 통과).
