# speech_lab — 오류 보존 받아쓰기 LoRA 실험실

이 폴더는 **실험용**이다. 채점 서버(`assessment/src/`)는 여기 있는 것을 하나도
쓰지 않고, 여기서도 `src/` 를 **읽기만 하고 고치지 않는다.** 실험 때문에 서비스
코드가 흔들리면 여기서 잰 숫자가 서비스의 숫자가 아니게 되기 때문이다.

## 무엇을 하려는 실험인가

상용 받아쓰기(Gemini·Azure)는 학습자가 틀리게 말한 것을 **조용히 고쳐서** 적는다.
실측으로 확인했다 — "안 돼습니다"라고 말해도 "안 됐습니다"로 적힌다.
고쳐 놓으면 채점기가 볼 오류가 사라지고, **틀린 응시자의 점수가 안 깎인다.**

그래서 Whisper 에게 "고치지 말고 들린 대로 적어라"를 다시 가르치려는 것이다.
가르치는 재료는 AI Hub 의 **오류 보존 사람 전사**다.

### 목표를 정확히 (여기가 급소)

목표는 "발음 그대로 적기"가 **아니다.**

- "여덟 시"의 표준 발음은 [여덜씨]다. 소리대로 적으면 **옳게 말한 사람에게
  가짜 오류가 생긴다.**
- "삼번"과 "3번"은 소리가 완전히 같다. 어느 쪽으로 쓰려 했는지 소리만 듣고
  알아낼 방법은 원리상 없다.

그래서 목표는 **"표준 철자로 적되, 소리로 구별되는 오류만 보존"** 이다.
소리로 구별 안 되는 표기 차이는 '말하기에서 측정 불가한 오류'로 선언하고
학습 정답에서도 지표 계산에서도 뺀다.
(근거: `assessment/RESEARCH.md` 의 '⑨의 구인 경계')

## 준비

```bash
# 이 컴퓨터(윈도우)에서 확인용으로 돌릴 때는 이미 다 깔려 있다.
# GPU 서버에서 학습할 때만:
pip install -r requirements-lab.txt
```

파이썬은 `C:\해커톤\.venv\Scripts\python.exe` 를 쓴다.
아래 명령은 전부 이 폴더(`assessment/scripts/speech_lab`)에서 실행한다.

원본 데이터는 `C:\해커톤\data\` 에 있고 git 에 올라가지 않는다.

| 이름 | 무엇 | 상태 |
|---|---|---|
| `Sample.zip` | AI Hub 71469 영어권 (16,021 파일) | 압축 그대로 |
| `Sample (1).zip` | AI Hub 71479 아시아어권 (23,564 파일) | 압축 그대로 |

라벨만 훑어보고 필요한 wav 만 꺼낸다.

## 다섯 단계 (순서대로)

### ① 데이터 뽑기 — `extract_pairs.py`

```bash
python extract_pairs.py --source 71479 --task LAR --max-n 200 \
    --out ../../../data/manifests/71479_lar.jsonl --extract-audio
```

- `--source` `71469`(영어권) / `71479`(아시아어권) / `505`
- `--task` `LAR`(낭독) / `ATQ`(자유발화) / `all`
- `--extract-audio` 를 붙이면 wav 를 `data/pairs/<source>/` 로 꺼내고
  **소리 크기 검사도 함께** 한다. 안 붙이면 목록만 만들어지고 소리 검사는 건너뛴다.

**정제 기준** (HUFS 한국어 L2 MDD 논문의 전처리 레시피를 물려받았다)

| 무엇 | 값 | 왜 |
|---|---|---|
| 낭독 길이 | 2~20초 | 20초 넘는 낭독은 더듬거나 다시 읽은 것 |
| 자유발화 길이 | 8~45초 | 8초 미만은 대답하다 만 것, 45초 초과는 학습 메모리 부담 |
| 화자당 최대 | 4건 | 몇 명 목소리가 데이터를 차지하면 그 사람 말투를 외운다 |
| 최소 소리 크기 | RMS 327.67 | 옆 사람 목소리만 든 녹음·거의 무음을 뺀다 |
| 전사 비었음 | 제외 | 정답지가 없으면 못 배운다 |
| wav 없음 | 제외 | 라벨만 있고 소리가 없는 짝이 실제로 있다 |

> 소리 크기 기준값 327.67 은 논문의 RMS 0.01 을 우리 눈금(0~32767)으로 옮긴 것이다.
> 71469 낭독 20건에서 실제 분포를 재 보니 **버려진 것 112~278 / 살아남은 말소리
> 872~4,556** 으로 사이가 뚜렷이 벌어져 있었다. 다만 341 로 아슬아슬하게 살아남은
> 건이 하나 있어, 데이터를 크게 늘릴 때 이 값은 한 번 더 봐야 한다.

**실측 결과**

| 원본 | 과제 | 뽑힌 수 | 평균 길이 | 비고 |
|---|---|---|---|---|
| 71479 | LAR | 40 / 40 요청 | 6.4초 | 베트남 10, 이란·몽골 각 4 … |
| 71479 | ATQ | 30 / 30 요청 | 20.6초 | 길이 기준으로 38건 걸러짐 |
| 71479 | all | 400 | — | LAR 285(오류 든 것 178·대조군 107) |
| 505 | all | 30 / 30 요청 | 13.1초 | 전부 영어 모어 |
| 71469 | LAR | **9 / 12 요청** | 6.1초 | 소리가 작아 3건 버려짐 |

### ② 정답지 검사하기 — `audit_kit.py`

**학습보다 먼저 해야 하는 단계다.** 우리 실험 전체가 "AI Hub 의 사람 전사는
학습자 오류를 그대로 살려 적었다"는 가정 위에 서 있는데, 그 가정이 깨진 사례를
이미 찾았다("같지"를 소리 나는 대로 "가치"라고 적어 놓은 것).
**정답지가 틀린 채로 가르치면 틀린 것을 열심히 외운 모델이 나온다.**

```bash
# 1) 팀원에게 줄 재료 만들기
python audit_kit.py --manifest ../../../data/manifests/71479_all.jsonl --n 100

# 2) 팀이 csv 를 다 채운 뒤 숫자 내기
python audit_kit.py --score --sheet ../../../data/audit/감사시트.csv
```

만들어지는 것 (`data/audit/`)

- `wav/` — 들어 볼 녹음 100개
- `감사시트.csv` — 채울 표 (엑셀로 열린다)
- `안내문.md` — 팀원용 설명서. **"외국인이 틀리게 말한 것은 정답지에도 틀리게
  적혀 있어야 정상"** 이라는 헷갈리는 지점을 예시로 풀어 놓았다

표본은 (과제 유형 × 국적)으로 고루 섞는다. 앞에서부터 자르면 특정 국적만
잔뜩 뽑혀서 "베트남 낭독의 신뢰율"을 전체 신뢰율이라 부르게 된다.

**실측**: 100건 표본을 뽑았고 과제·국적별로 최대 6건씩 고르게 퍼졌다.
`--score` 는 시험용으로 40건을 채워 넣어 신뢰율 80.0%, 불일치 8건 표시,
약속 안 된 표기(`??`) 1건 경고까지 나오는 것을 확인했다.
**아직 팀이 실제로 듣고 채운 숫자는 없다 — 그건 사람이 해야 한다.**

### ③ 학습 정답 만들기 — `make_labels.py`

```bash
python make_labels.py --manifest ../../../data/manifests/71479_lar.jsonl \
    --variant flagship --out ../../../data/labels/flagship.jsonl
```

두 갈래가 있다.

- `--variant flagship` (본진) — 사람 전사를 그대로 정답으로 쓰되 **구인 경계**만 적용
- `--variant mdd` (비교용) — 전사를 발음 표기로 바꾼다(g2pk). 위에서 말한
  '가짜 오류' 문제를 안고 가는 방식이며, 비교 상대로 두려고 만든다

**flagship 이 지금 하는 일** (`converge_inaudible`)

| 규칙 | 예 |
|---|---|
| 자모 결합 정리(NFC) | 눈에 같아 보여도 속으로 다른 글자를 맞춘다 |
| 전사 기호 제거 | `한국에서 있+ 오는` → `한국에서 있 오는` |
| 〃 | `어/ 우리나라가` → `어 우리나라가` |
| 문장부호 통일·공백 정리 | `‘ ’ “ ” …` 를 한 모양으로 |

`+`(말 끊김)와 `/`(군말)는 **전사자가 붙인 표시**이지 응시자가 낸 소리가 아니다.
그래서 기호만 떼고 글자(`있`, `어`)는 남긴다.
**학습자 오류는 손대지 않는다** — `비쌌다` 는 `비쌌다` 그대로 간다.

> **아직 없는 것(TODO)**: 동음이표기 사전(여덟/여덜, 돼/됐)을 이용한 실제 수렴.
> 어느 쪽이 표준형인지 판정하려면 발음 변환기가 필요한데 윈도우에 설치가 안 된다.
> 자리(`converge_inaudible` 안의 ⑤번)는 만들어 뒀고 GPU 서버에서 채운다.
> **그때까지 오류 보존율에는 이만큼의 거품이 남아 있다고 보고 읽어야 한다.**

**실측**: 505 세트 20건으로 돌려 라벨 20건 생성, 그중 6건이 전사 기호 제거로 다듬어졌다.

**g2pk 설치 결과 — 실패**

| 시도 | 결과 |
|---|---|
| `pip install g2pk` | 실패 — `python-mecab-ko` 를 C 로 빌드해야 하는데 윈도우에 빌드 도구가 없다 |
| `pip install g2pkk` (순수 파이썬 포크) | 설치는 됨. 그러나 실행 시 `eunjeon`(윈도우용 mecab)을 요구하고 그것도 빌드 실패 |

→ `--variant mdd` 는 이 컴퓨터에서 **만들 수 없다.** 스크립트가 그 사실과 함께
"리눅스에서는 `pip install g2pk` 한 줄로 된다"는 안내를 출력하고 멈춘다.
`--variant flagship` 은 정상 동작한다.

### ④ 학습하기 — `train_lora.py`

**이 컴퓨터에서는 학습하지 않는다.** 여기서는 확인만 한다.

```bash
# 확인 (CPU, 1분 정도)
python train_lora.py --data ../../../data/labels/505_flagship.jsonl --dry-run
```

`--dry-run` 이 확인하는 것 넷: 데이터가 읽히는가 / 모델이 조립되는가 /
묶음이 만들어지는가 / 계산이 끝까지 가서 손실값이 나오는가.

**실측 (통과)**

```
① 데이터 4건 읽음
② 모델 조립 완료   trainable params: 1,769,472 / 243,504,384 (0.7267%)
③ 묶음 만듦 · 소리 (2, 80, 3000) · 정답 (2, 73)
④ 한 걸음 계산 성공 · 손실값 1.8873
```

전체의 0.73%만 배운다는 것이 LoRA 가 제대로 걸렸다는 뜻이다.

기본값: whisper-small · LoRA r=16(q_proj·v_proj) · fp16 · epochs 5 · batch 8 ·
lr 1e-5 · **seed 42 고정**. 끝나면 **어댑터만** 저장한다(수십 MB).

### ⑤ 견주기 — `eval_ab.py`

```bash
python eval_ab.py --manifest ../../../data/manifests/71479_lar.jsonl \
    --model base --model gemini --max-n 16
```

`--model` 에 넣을 수 있는 것: `base`(faster-whisper) / `base:medium` /
`gemini`(지금 채점 서버가 쓰는 그 경로) / 어댑터 폴더 경로.

**지표 세 개**

1. **CER** — 글자 오류율. 낮을수록 정확. 기본기 확인용
2. **오류 보존율** — 학습자 오류 중 전사에 살아남은 비율. **여기가 승부처다.**
   낭독에서만 잴 수 있다(읽어야 했던 문장이 있어야 어디서 틀렸는지 안다)
3. **대조군 오탐율** — 옳게 말한 사람에게 없는 오류를 만들어 내는 비율.
   2번만 재면 "다 틀리게 적는 모델"이 1등이 되므로 반드시 짝으로 본다

> 지표 2는 우리가 처음 만든 것이 아니다. ACL 2024 *"Error-preserving ASR of Young
> English Learners"* (Michot et al., ZHAW)가 **WEPR** 로 먼저 정의했고, 우리는 그
> 정의를 한국어 어절 단위로 옮겨 쓴다. 우리 몫은 '한국어 L2 + 이 전사로 채점하면
> 사람 점수와 더 맞는가(QWK)'까지 가는 것이다. 부품 출처를 먼저 밝히고 시작한다.

**실측 (71479 낭독 16건 — 오류 든 것 10건 · 대조군 6건)**

| 모델 | CER | 오류보존율 | 보존/세탁/기타 | 대조군오탐율 | 걸린시간 |
|---|---|---|---|---|---|
| base(whisper-small) | 14.9% | 60.0% | 9 / 6 / 9 | 33.3% | 30초 |
| gemini(3.1-flash-lite) | 10.8% | 66.7% | 12 / 6 / 6 | 33.3% | 52초 |

두 번 돌려 같은 값이 나오는 것까지 확인했다.

**읽을 때 주의할 것**

- 16건은 **너무 적다.** 방향만 보는 숫자이고 주장의 근거로 쓰면 안 된다.
- `기타`(다르게 알아들음)가 아직 많다. 학습 전 기본 Whisper 라 당연하기도 하다.
- 8/2 파일럿의 72.5% 와 **그대로 견주면 안 된다.** 그때 판정 규칙에는
  '한쪽이 다른 쪽을 품은 경우'(표준형 `방` / 발화형 `방청소를`)를 다루는 갈래가
  없어서 그런 자리가 전부 `기타` 로 빠졌다. 지금은 긴 쪽이 전사에 있는지로
  판정한다 — 이 한 줄로 gemini 보존율이 62.5% → 66.7% 로 올랐다.

## GPU 서버에서 돌리는 순서

윈도우 노트북에서 할 수 있는 데까지가 위까지다. 실제 학습부터는 리눅스 GPU가 필요하다.
Colab 무료 GPU 로도 되고, 더 크게 돌리려면 RunPod 4090 대여가 시간당 몇백 원이다.

1. **로컬에서 재료를 다 만든다.** `extract_pairs.py --extract-audio` 로 wav 까지
   꺼내고 `make_labels.py --variant flagship` 으로 라벨 JSONL 을 만든다.
2. **감사를 먼저 끝낸다.** 팀이 `감사시트.csv` 를 채우고 `--score` 로 신뢰율을
   확보한다. 신뢰율이 낮게 나온 유형은 라벨에서 빼고 다시 ①로 간다.
   **이 단계를 건너뛰면 틀린 정답지를 GPU 값 치르며 외우게 된다.**
3. `speech_lab/` 폴더와 `data/pairs/`, `data/labels/` 를 서버로 올린다
   (wav 가 크므로 필요한 것만).
4. 서버에서 `pip install -r requirements-lab.txt`. 여기서 `g2pk` 가 비로소 깔리므로
   `--variant mdd` 라벨도 이때 만든다.
5. `python train_lora.py --data labels/flagship.jsonl --dry-run` 으로 서버에서도
   한 번 확인한 뒤, `--dry-run` 을 떼고 진짜 학습을 돌린다.
6. 끝나면 **어댑터 폴더를 먼저 내려받고** 서버를 끈다. RunPod 은 이렇게 이어 붙인다.

   ```bash
   python train_lora.py --data labels/flagship.jsonl --out adapters/v1 \
       && runpodctl stop pod $RUNPOD_POD_ID
   ```

   `&&` 는 '앞이 성공하면 뒤를 실행하라'는 뜻이다. 실패하면 서버가 살아 있어서
   로그를 볼 수 있다. **서버를 끄면 디스크가 사라진다.**
7. 돌아와서 `eval_ab.py --model base --model gemini --model adapters/v1` 로
   3자 비교표를 뽑는다. 이게 이 실험의 결과물이다.
