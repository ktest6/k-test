# items — 문항 세트

시험에서 응시자에게 제시할 문항 원본입니다. **백엔드가 이 파일을 DB에 등록**하고,
채점할 때 `POST /score` 의 `item` 필드에 문항 하나를 그대로 담아 보냅니다.
`items[]` 안의 객체는 `ScoreRequest.item`(ItemInfo) 형식과 일치합니다.

## 파일

| 파일 | 내용 | 상태 |
|---|---|---|
| `writing_v0.json` | 쓰기 문항 5개 | **초안 — 검수 전** |
| `speaking_v1.json` | 말하기 문항 6개 (이미지 제시형 4: 표지 2 · 사진 2 / 음성 질문형 2). 가중치 임시 · 회의 후 확정, SPK-104 c6 는 A안 임시 | **초안 — 검수 전** |
| `archive/speaking_v0.json` | 예전 말하기 테스트 문항 5개. 지금은 변형 검사(`scripts/metamorphic/cases.json`)에서만 쓴다 | 보관 |

## 쓰기 문항 5개가 재는 것

전부 실제 직무 상황에서 그대로 가져온 과제입니다.

| id | 유형 | 상황 | 체크리스트가 요구하는 것 |
|---|---|---|---|
| WRT-001 | 작업일지 | 하루 작업 기록 | 작업 내용 / 문제 / 처리 결과 |
| WRT-002 | 메신저 보고 | 아파서 결근 연락 | 결근 사실 / 이유 / 복귀 시점 / 높임 |
| WRT-003 | 위험 신고 | 기울어진 선반 신고 | 무엇이 위험한지 / **어디인지** / 조치 요청 |
| WRT-004 | 인수인계 메모 | 교대 근무자에게 메모 | 끝낸 일 / 남은 일 / 주의사항 |
| WRT-005 | 자재 요청 | 장갑 부족 요청 | 품목 / 수량 / 기한 |

## 말하기 문항 6개가 응시자에게 주는 것

응시자가 보거나 듣는 자료는 `image`(그림 파일 이름) 또는 `audio`(질문 소리 파일 이름)에
파일명만 적혀 있습니다. **둘 다 화면·스피커에 무엇을 띄울지 고르는 값일 뿐 채점에는 쓰지 않습니다.**
채점하는 AI 는 그림을 보지도 소리를 듣지도 못하므로, 그림 내용은 `scene_description` 에,
질문 문장은 `prompt` 에 글로 그대로 옮겨 둡니다.

| id | 유형 | 제시 자료 | 응시자가 하는 일 |
|---|---|---|---|
| SPK-101 | `sign_description` | 그림 (비상대피로 표지) | 표지의 뜻을 말로 설명 |
| SPK-102 | `sign_description` | 그림 (근로자 쉼터 표지) | 표지의 뜻을 말로 설명 |
| SPK-103 | `picture_description` | 그림 (망치질하는 작업자) | 사진 속 행동을 묘사 |
| SPK-104 | `hazard_warning` | 그림 (안전모 없이 사다리) | 동료에게 위험과 조치를 알림 |
| SPK-105 | `answer_question` | 소리 (`SPK-105.wav`) | "왜 늦으셨나요?" 질문에 대답 |
| SPK-106 | `answer_question` | 소리 (`SPK-106.wav`) | "못에 찔렸을 때는?" 질문에 대답 |

질문 소리 파일(`SPK-105.wav`, `SPK-106.wav`)은 우리가 만들지 않습니다. 파일이 아직 없어도
질문 문장이 `prompt` 에 들어 있어 채점은 지금 그대로 돕니다.

## 체크리스트 작성 원칙

**'관련성'이 아니라 '완수'가 기준입니다.**
위험 신고에서 위치를 빠뜨린 글은 관련 있는 글일지 몰라도 **실패한 보고**입니다.
그래서 WRT-003 은 위치(c2)에 1.5 가중치를 둡니다. 현장에서 빠지면 사고로
이어지는 정보일수록 가중치가 높습니다.

### 체크리스트 항목의 필드

| 필드 | 쓰임 |
|---|---|
| `description` | **채점 기준.** LLM 이 이 한국어 문장을 읽고 충족/미충족을 판정합니다. 바꾸면 채점이 바뀝니다 |
| `description_en` | **화면 표시용.** 리포트의 'Required Points' 칸에 뜨는 영어 한 문장입니다. 채점에는 쓰지 않으며, 응시자에게 시키는 말 꼴로 씁니다(예: `Tell him to wear a safety helmet.`) |
| `weight` | 항목별 비중 (0.5 ~ 1.5) |
| `requires` | **이 항목을 LLM 에게 묻지 않고 앞 항목들의 판정으로 계산**할 때 쓰는 조건 |

`description_en` 은 선택 필드입니다. 없으면 빈 문자열로 채점이 그대로 돕니다.

### `requires` — 마지막 [보너스] 항목을 코드가 계산합니다

`"requires": [["c4"], ["c3"], ["c5", "c6"]]` 는 **바깥이 '그리고', 안쪽이 '또는'** 이라서
"c4 충족 그리고 c3 충족 그리고 (c5 또는 c6) 충족" 이라는 뜻입니다. 비워 두면 지금까지처럼 LLM 이 판정합니다.
"세 요소를 모두 포함했는가" 같은 보너스 항목은 근거가 답안 여기저기 흩어져 있어서 LLM 이 인용을
이어 붙여 내고, 그 인용이 원문에 없다는 이유로 폐기돼 억울하게 0점이 되었기 때문입니다(SPK-105 c10 실측).
**가리키는 항목은 자기보다 앞에 있어야 합니다** — 뒤를 가리키거나 없는 id 를 적으면 경고와 함께 미충족이 됩니다.

## 지시문 작성 원칙

응시자는 한국어 학습자입니다. **지시문이 시험 대상보다 어려우면 측정이 오염됩니다.**

- 짧은 문장, 쉬운 낱말만 사용 ("기록하세요·포함하세요" 대신 "쓰세요")
- 요구 항목은 ① ② ③ 번호로 명시 — 무엇을 써야 하는지 추측하게 하지 않는다
  (측정 대상은 한국어 능력이지 눈치가 아니다)

## expected_register (요구 말투)

| 값 | 뜻 | 적용 문항 |
|---|---|---|
| `formal` | 합쇼체 중심 (공식 기록·보고) | WRT-001, 003, 005 |
| `polite` | 해요체 허용 (메시지·메모) | WRT-002, 004 |

## 아직 안 된 것

- **사람 검수.** 이 문항들은 초안입니다. 팀 검수 후 `status` 를 `confirmed` 로 바꿉니다.
- **문항별 가중치 프로필.** 현재는 모든 문항이 내용 45 : 언어 55 의 공통 임시
  가중치(`provisional_v0`)로 채점됩니다. 유형별 프로필(예: 위험 신고는 내용 비중↑)은
  라벨 데이터가 생긴 뒤 정합니다.
- **말하기 문항.** Azure 도입과 함께 별도 파일로 추가합니다.
