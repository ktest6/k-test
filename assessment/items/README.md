# items — 문항 세트

시험에서 응시자에게 제시할 문항 원본입니다. **백엔드가 이 파일을 DB에 등록**하고,
채점할 때 `POST /score` 의 `item` 필드에 문항 하나를 그대로 담아 보냅니다.
`items[]` 안의 객체는 `ScoreRequest.item`(ItemInfo) 형식과 일치합니다.

## 파일

| 파일 | 내용 | 상태 |
|---|---|---|
| `writing_v0.json` | 쓰기 문항 5개 | **초안 — 검수 전** |

## 쓰기 문항 5개가 재는 것

전부 실제 직무 상황에서 그대로 가져온 과제입니다.

| id | 유형 | 상황 | 체크리스트가 요구하는 것 |
|---|---|---|---|
| WRT-001 | 작업일지 | 하루 작업 기록 | 작업 내용 / 문제 / 처리 결과 |
| WRT-002 | 메신저 보고 | 아파서 결근 연락 | 결근 사실 / 이유 / 복귀 시점 / 높임 |
| WRT-003 | 위험 신고 | 기울어진 선반 신고 | 무엇이 위험한지 / **어디인지** / 조치 요청 |
| WRT-004 | 인수인계 메모 | 교대 근무자에게 메모 | 끝낸 일 / 남은 일 / 주의사항 |
| WRT-005 | 자재 요청 | 장갑 부족 요청 | 품목 / 수량 / 기한 |

## 체크리스트 작성 원칙

**'관련성'이 아니라 '완수'가 기준입니다.**
위험 신고에서 위치를 빠뜨린 글은 관련 있는 글일지 몰라도 **실패한 보고**입니다.
그래서 WRT-003 은 위치(c2)에 1.5 가중치를 둡니다. 현장에서 빠지면 사고로
이어지는 정보일수록 가중치가 높습니다.

## 지시문 작성 원칙

응시자는 한국어 학습자입니다. **지시문이 시험 대상보다 어려우면 측정이 오염됩니다.**

- 짧은 문장, 쉬운 낱말만 사용 ("기록하세요·포함하세요" 대신 "쓰세요")
- 요구 항목은 ① ② ③ 번호로 명시 — 무엇을 써야 하는지 추측하게 하지 않는다
  (측정 대상은 한국어 능력이지 눈치가 아니다)

## expected_register (요구 말투)

| 값 | 뜻 | 적용 문항 |
|---|---|---|
| `formal` | 합쇼체 중심 (공식 기록·보고) | WRT-001, 003, 005 |
| `polite` | 해요체 허용 (메시지·메모) | WRT-002, 004 |

## 아직 안 된 것

- **사람 검수.** 이 문항들은 초안입니다. 팀 검수 후 `status` 를 `confirmed` 로 바꿉니다.
- **문항별 가중치 프로필.** 현재는 모든 문항이 내용 45 : 언어 55 의 공통 임시
  가중치(`provisional_v0`)로 채점됩니다. 유형별 프로필(예: 위험 신고는 내용 비중↑)은
  라벨 데이터가 생긴 뒤 정합니다.
- **말하기 문항.** Azure 도입과 함께 별도 파일로 추가합니다.
