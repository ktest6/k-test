## 8/2

- **계단4 말하기판 완승: 생 LLM에게 음성을 직접 채점시켰더니 무음에 95점 A를 줬다.** "세 요소를 명확하게 표현했다"는 이유까지 지어냈고, 영어로 답해도 95점 A를 발급했다. 같은 모델을 쓰는 우리 파이프라인은 무음 503 차단·영어 무효 처리. 정상 답안도 저쪽은 3회 다 95 A(만점 남발), 우리는 77.09 B 세분 점수. 원자료: `outputs/stair4_speaking_20260802.json`.
- **문제 발견(공격 실험): 무음 음성을 넣었더니 받아쓰기가 모범답안을 지어내서 78점(B)이 나왔다.** 받아쓰기 정확도용으로 문항 지시문을 힌트로 주는데, 소리가 없으면 그 힌트로 답을 상상해 버린다(STT 환각). → **해결: 받아쓰기 모델을 부르기 전에 소리 크기를 직접 재서 막는다**(`src/speech/loudness.py`). 파일 안의 숫자만 보는 계산이라 모델이 무엇을 하든 결과가 같다. 같은 공격이 이제 78.07점 B 대신 503(그 문항 미채점)으로 나가고, 잰 값이 사유에 함께 붙는다. 나머지 공격 4종(베트남어·영어 발화, 지시문 낭독, 한 마디)은 기존 가드가 전부 막았다.
- **정직한 기록: "말이 없으면 빈 글을 내라"는 지시는 무음을 못 막았다.** 지시를 강하게 고쳐 쓴 뒤에도 같은 무음 파일에 모델은 `has_speech: true` 와 함께 답안을 지어냈다. 그래서 지시(2겹)는 보조일 뿐이고 실제로 막는 것은 소리를 재는 관문(1겹) 하나다. **남은 구멍: mp3·m4a 같은 압축 형식은 소리를 풀어 봐야 잴 수 있어서 이 관문을 건너뛴다**(ffmpeg 가 필요해 미도입).
- **문제**: 무음 가드를 넣으면서 "말소리 없으면 false" 만 적었더니 모델이 **영어 발화까지 '말 없음'으로 답해서** 외국어 답안이 낮은 점수 대신 미채점(503)이 됐다 → **해결**: "한국어가 아니어도 사람이 말하고 있으면 말소리다"를 지시에 못 박고 실호출로 원래대로 돌아온 것을 확인했다.
- 기준값은 실측으로 잡았다. 정상 TTS 발화의 가장 큰 0.1초는 8,519~13,318(0~32767 눈금), 무음은 0. 무음으로 보는 선은 **15**(정상 발화의 1/570), 너무 조용해서 못 믿는 선은 **60**. `scripts/check_loudness.py` 로 언제든 값을 다시 볼 수 있다(LLM·네트워크 없이 돈다).
- **진짜 사람 목소리로 말하기 첫 실측.** 녹음(m4a) → 받아쓰기(군말 "어..."까지 그대로) → 58.09점(C). 3요소 중 "다음 지시 요청"을 안 말했더니 정확히 그 항목만 X — 변별이 실제 목소리에서도 작동. 받아쓰기 2회 결과 글자까지 동일.
- **대상 전략 확정: 증명은 AI Hub 실제 외국인 발화 데이터로.** 정답 전사가 붙어 있어 받아쓰기 정확도(CER)를 숫자로 만들 수 있고, 사람 평가 점수가 붙은 세트는 기계-인간 일치율 재료. 데이터 신청은 승인 대기가 있어 즉시 신청하기로. LoRA 는 "채점 모델에는 안 쓰고(재현성 무기 훼손), Whisper 받아쓰기 학습에만 조건부"로 결론 — PLAN 에 착수 조건과 함께 기록.
- **말하기 문항 5개 초안 완성** (`items/speaking_v0.json` — 고장 보고·위험 알림·지시 재진술·완료 보고·도움 요청). 지시 재진술 문항으로 실측: 완전한 답 82.9점(B), 절반 빠진 답 43.3점(D) — 문항이 잘하는 사람과 못하는 사람을 가른다.
- **말하기 음성 입력 완성 — 음성 파일 주소를 주면 받아쓰고 채점까지 간다.** `POST /score` 에 `audio: {url}` 필드가 늘었다. 진짜 음성(11.8초)으로 실호출: 받아쓰기 2.6~3.7초, 글자 일치율 95.8%, 종합 77.09점(B)까지 완주. 확인 스크립트가 음성을 잠깐 로컬 웹서버에 올려서 **진짜 다운로드 경로까지** 태운다.
- **Azure 로 갈아 끼울 수 있는 구조로 만들었다.** `src/speech/port.py` 가 꽂는 자리이고 지금은 Gemini 가 꽂혀 있다. Azure 계정이 나오면 고칠 곳은 `intake.py` 의 함수 하나이고 **백엔드가 보는 API 형식은 안 바뀐다**(`meta.stt_provider` 값만 `azure` 가 된다).
- **문제**: 받아쓰기가 응시자의 문법 오류를 몰래 고쳤다. "안 돼습니다"를 "안 됐습니다"로, "삼번"을 "3번"으로. 오류가 지워지면 그 응시자는 감점을 안 받는다 → **해결 못 했다(정직한 기록)**. "고치지 말라"는 지시에 더해 그 두 개를 그대로 보기로 넣어 줬는데도 똑같이 고쳤다. **이유는 소리로 구별이 안 되는 자리이기 때문**이다("삼번"과 "3번"은 소리가 완전히 같다). 프롬프트로 될 일이 아니고 Azure 로 바꿔도 남을 가능성이 크다. 코드 설명과 README 에 실측 그대로 적어 뒀다.
- **발견**: 같은 음성을 두 번 받아쓰면 **글자 하나까지 같았다.** 채점 재현성의 전제가 지켜진다.
- **채점기는 거의 안 건드렸다.** `src/features`·`src/llm`·`src/generation` 변경 0. `src/scoring` 은 계약 파일에 필드를 더한 것과 `pipeline.py` 배선 몇 줄뿐이고, 점수 계산(`combine.py`·`finalize.py`)은 한 줄도 안 바뀌었다. 그 사실을 테스트로도 막아 뒀다.
