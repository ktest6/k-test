실제 답안을 보고 체크리스트를 만들면 어떨까

요청은 두 가지였다 — ① 가상 답안을 지어내지 말고 AI Hub 실제 답안을 보고 체크리스트를 만들 것 ② 판정을 O/X 대신 확률로 받아 가중치를 다시 학습할 것. 하나는 했고, 하나는 API 가 막았다.

날짜 2026-08-09 표본 답안 281건 · 문항 9종 (1·2차와 동일) 체크리스트 문항 9종 × 5겹 = 45벌 모델 gemini-3.1-flash-lite · 본 판정 온도 0 LLM 호출 2,065회 · 실패 0건

한 줄 결론

실제 답안을 보여 줬더니 체크리스트가 오히려 짧아졌고(항목 6개 → 3.5개), 점수도 2차보다 유의하게 낮았다 (J 0.608 vs F 0.698, 차이 -0.091). 확률 판정은 Gemini API 가 막아서 불가능했고, 씨앗을 바꿔 확률을 흉내 내는 대체재도 실측 결과 표가 갈린 칸이 8.2% 뿐이라 쓸 수 없다고 판정했다. 다만 세 번째로 같은 진단이 나왔다 — 이 문항들은 요구하는 것이 원래 두 가지뿐이다.

요청 ①

실제 답안을 보고 만들되, 답을 보고 시험지를 만들지 않도록

2차는 지어낸 가상 답안 4개를 보고 항목을 뽑았다. 이번엔 팀원 요청대로 진짜 응시자 답안을 보여 줬다. 각 답안에 사람이 매긴 점수(0~5)를 함께 붙여서, “5점과 1점이 무엇이 달랐는가”를 보고 변별하는 항목을 뽑게 했다.

여기서 함정이 하나 있다. 시험 볼 답안을 보고 체크리스트를 만들면 답을 보고 시험지를 만든 것이 된다. 그래서 겹마다 체크리스트를 따로 만들었다 — 겹 k 의 시험지는 겹 k 답안을 한 건도 보지 않고, 나머지 4겹에서 점수대가 고르게 퍼지도록 뽑은 8건만 보고 만든다. 문항 9종 × 5겹 = 45벌. 프로그램으로 감사한 결과 시험 겹 답안이 생성 프롬프트에 섞인 경우는 0건이었다.

2차 6개 → 3차 평균 3.5개. “진짜 답안을 보여 주면 더 풍부해질 것”이라는 예상과 정반대다. 모델이 실제 답안에서 찾아낸 변별축은 대체로 “무엇을 말했나 · 왜인지 말했나” 둘뿐이었다. 1차·2차에 이어 세 번째로 같은 진단 — 병목은 생성 방식이 아니라 이 문항들이 요구하는 것 자체가 얕다는 데 있다.

대신 얻은 것도 있다. 2차에서 문제였던 부정형 항목(“~을 배제했는가”)이 이번엔 158개 중 6개(3.8%)로 억제됐다. 없는 것을 원문에서 인용할 수 없어 무더기로 폐기되던 사고가 크게 줄었다.

대신 새로 치른 값 — 겹마다 시험지가 달라진다. 같은 문항의 5 벌을 서로 견주니 문구 닮음이 평균 0.331, 짝이 생긴 항목이 27.1% 였다. 데이터를 보고 만드는 방식은 어떤 답안을 보여 주느냐에 따라 시험지가 흔들린다는 뜻이고, 이것은 표준화 시험에서 비용이다.

진 이유는 ‘항목이 너무 쉬웠다’로 잡힌다

v3 항목의 평균 통과율이 65.4% 였고, 281건 중 95건이 모든 항목을 통과했다(반대로 29건은 전부 미충족). 사람이 5 점 준 답안과 2 점 준 답안이 똑같이 만점을 받으면 가를 방법이 없다. 실제 답안을 보여 주자 모델이 “이 정도면 됐다”는 느슨한 기준을 배운 것으로 보인다 — 지어낸 답안(2차)에는 일부러 만든 못난 답안이 섞여 있어 기준이 더 팽팽했다.

변하지 않은 것

재현성은 세 번 다 100%

고정 60 건을 3 회 판정한 결과 최종 점수 완전일치 100%, 항목 0/1 뒤집힘 0/0칸. 1·2차와 같다. 세 차례 실험에서 재현성으로는 한 번도 우열이 갈리지 않았다 — 이 판정 모델이 짧은 판정에서 결정적이기 때문이다.

세 차례를 합쳐서

지금까지 알아낸 것

  1. 이 시험지에서는 LLM 직접 채점이 계속 이긴다(0.787). 체크리스트 최고는 v2+학습 0.698 다.
  2. 체크리스트를 살리는 것은 결합 방식이 아니라 항목이다. 세 번 모두 “충족 개수만 세기”는 제자리였고, 항목별 비중을 배우는 방식만 천장을 따라 움직였다.
  3. 항목을 늘리는 방법은 지어낸 후보 답안(2차) 쪽이 낫다. 진짜 답안을 보여 주면 기준이 느슨해져 항목이 줄고 쉬워진다.
  4. 세 번 모두 같은 진단: AI Hub 문항의 요구가 원래 둘뿐이다. 요구가 3~5 개인 우리 직무 문항에서 다시 재야 한다.
  5. LLM 이 매기는 중요도는 세 번 다 효과가 없었다. 비중은 데이터에서 배우는 쪽이 낫다.

다음에 할 것

  1. 우리 직무 문항으로 2차(v2) 방식을 다시. 3차 방식이 아니라 2차 방식이 기준선이다.
  2. 두 방식을 합치기. LLM 직접 점수와 체크리스트 항목을 함께 자질로 넣어 결합 모델을 학습시킨다.
  3. 확률 판정을 정말 보려면 Vertex AI 또는 GPU 를 붙여야 한다. 그때는 같은 모델로 이진·확률을 둘 다 돌린다.
  4. 항목을 더 어렵게. 통과율 65% 는 너무 후하다. “최소한만 말한 답안은 떨어지는 항목”을 반드시 섞게 해야 한다.

정직하게

이 결과로 말할 수 없는 것

  • 겹마다 체크리스트가 다르다. 같은 문항인데 응시자마다 다른 시험지로 채점되는 셈이라, 실제 시험에 쓰려면 한 벌로 굳히는 절차가 따로 필요하다.
  • 체크리스트를 만들 때 사람 점수를 보여 주었다. 학습 겹 점수만 보았으므로 시험 겹 누출은 없지만, 사람 점수가 없는 새 문항에는 이 방식을 그대로 쓸 수 없다.
  • 문항당 답안이 27~40건뿐이고, J 는 겹마다 항목 수만큼의 가중치를 20~32건으로 배운다. 과적합 위험이 v2 보다 크지는 않지만 표본이 작다.
  • 천장(선형 적합)은 항목이 많을수록 저절로 올라간다. 겹벌 천장으로만 v2 와 견줘야 한다.
  • AI Hub 데이터는 우리 시험(직무 한국어)과 과제 성격이 다르다.
  • 판정 모델은 gemini-3.1-flash-lite 하나뿐이다. 다른 모델에서도 같은 순위가 나올지는 안 쟀다.
