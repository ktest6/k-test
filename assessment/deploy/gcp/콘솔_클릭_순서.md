# GCP 콘솔에서 시연 서버 만들기 — 클릭 순서

9/2 시연장에서는 재완이 PC 를 못 쓴다. 그래서 지금 내 PC 에서 돌던 서버 둘을
구글 클라우드(GCP)의 그래픽카드 컴퓨터로 옮겨 **계속 켜 둔다.**

| | 무엇 | 포트 | 누가 부르나 |
|---|---|---|---|
| 1 | 채점 서버 | 8001 | 백엔드 서버가 인터넷으로 부른다 → **바깥에 연다** |
| 2 | LoRA 받아쓰기 서버 | 8100 | 채점 서버가 같은 컴퓨터 안에서 부른다 → **바깥에 안 연다** |

이 PC 에는 `gcloud` 명령이 깔려 있지 않다. 그래서 **전부 웹 브라우저의 GCP 콘솔에서
마우스로** 한다. 아래 순서를 위에서부터 그대로 따라 하면 된다.

> ## 이미 만들어 둔 VM 이 있다면 (8/25)
>
> 8/25 에 VM 하나를 이미 만들었다 — **`stt-lora`** · us-east1-c · **NVIDIA L4** ·
> g2-standard-4 · 디스크 100GB · Deep Learning 이미지(CUDA 12.9).
> 그때는 받아쓰기 서버 하나만 홈 폴더에서 임시로 띄우는 방식이었다
> (`scripts/speech_lab/gcp/setup_lora_vm.sh` — 창을 닫으면 꺼진다).
>
> **새로 만들 필요 없다.** 그 VM 에 그대로 4단계부터 하면 된다. 다만 두 가지는
> 챙겨야 한다.
> - **1단계(고정 IP)와 3단계(방화벽 8001)** 는 아직 안 했을 가능성이 크다. 먼저 한다.
> - 이미 켜져 있는 임시 받아쓰기 서버가 8100 을 잡고 있으면 systemd 서비스가 못 뜬다.
>   `pkill -f lora_stt_server.py` 로 먼저 내린다.
>
> 처음부터 새로 만들 때만 1~3단계를 그대로 따른다.

## 미리 챙길 것 두 가지

이 둘이 없으면 서버를 만들어 놔도 채점이 안 된다. 먼저 준비해 둔다.

1. **`v2_adapter.tar.gz`** — 우리가 학습한 LoRA v2 어댑터 압축 파일.
   내 PC 의 `D:\해커톤데이터\adapters` 밑에 있는 것을 압축해 두면 된다.
2. **열쇠 값들** — Gemini 열쇠, Azure 음성 열쇠·지역.
   지금 `assessment\.env` 에 들어 있는 값을 메모장에 옮겨 둔다.
   (이 문서에도, 저장소 어디에도 값을 적지 마라.)

## 1단계 — 고정 주소(외부 IP) 먼저 예약하기

주소를 먼저 잡아 두는 까닭: VM 을 껐다 켜면 **주소가 바뀐다.** 그때마다 백엔드에
새 주소를 알려 주는 것은 시연 전날 사고의 지름길이다. 안 바뀌는 주소를 미리 잡는다.

1. 콘솔 위쪽 검색창에 **`IP 주소`** 를 치고 **VPC 네트워크 → IP 주소** 로 들어간다.
2. **[외부 고정 주소 예약]** 을 누른다.
3. 이렇게 채운다.
   - 이름: `ktest-demo-ip`
   - 네트워크 서비스 계층: **프리미엄**
   - IP 버전: **IPv4**
   - 유형: **리전**
   - 리전: **asia-northeast3 (서울)**  ← 시연장이 한국이라 가장 가깝다
     **단, 이미 있는 `stt-lora` VM 을 쓸 거면 그 VM 과 같은 리전(us-east1)으로 잡는다.**
     리전이 다르면 그 VM 에 붙일 수 없다.
4. **[예약]** 을 누른다. 목록에 나온 주소(예: `34.64.xx.xx`)를 **메모해 둔다.**
   이것이 앞으로 백엔드에 줄 주소다.

> 이미 돌고 있는 VM 에 고정 IP 를 붙이려면: VM 인스턴스 → 해당 VM → [수정] →
> 네트워크 인터페이스 → 외부 IPv4 주소에서 예약해 둔 것을 고르고 [저장].
> **주소가 바뀌므로 백엔드에 새 주소를 다시 알려 줘야 한다(이번 한 번만).**

> 주의: 예약해 놓고 아무 VM 에도 안 붙여 두면 **안 쓰는 값이 따로 나간다**(월 몇 달러).
> 시연이 끝나면 예약을 해제한다.

## 2단계 — VM 만들기

1. 검색창에 **`VM 인스턴스`** → **Compute Engine → VM 인스턴스** → **[인스턴스 만들기]**

2. **이름·자리**
   - 이름: `ktest-demo`
   - 리전: **asia-northeast3 (서울)** ← 1단계에서 IP 를 잡은 리전과 **같아야 한다**
   - 영역: `asia-northeast3-b` (아무거나, GPU 가 있는 영역이면 된다)

3. **머신 (그래픽카드)** — [GPU] 칸을 고른다.
   - **g2-standard-4** (GPU: **NVIDIA L4** 1장, vCPU 4 · 메모리 16GB) ← 이걸로 한다
   - 더 싼 **n1-standard-4 + T4** 를 먼저 노려 볼 수는 있다. 하지만 **8/25 에
     us-central1-b · us-east1-c 두 영역에서 T4 가 "currently unavailable"(재고 없음)
     이었다.** 쿼터 문제가 아니라 남은 카드가 없다는 뜻이라 기다려도 소용없다.
     그래서 L4 로 갔고 바로 됐다.
   - GPU 가 "이 영역에 없음" 이라고 나오면 영역을 `-a`·`-b`·`-c` 로 바꿔 보고,
     그래도 없으면 리전을 바꾼다(서울에 없으면 us-east1 등).

   > 왜 이 정도면 되나: 우리가 돌리는 것은 **학습이 아니라 받아쓰기(추론)** 다.
   > whisper-small 은 작은 모델이라 8/22 에 내 PC 의 RTX 4060 에서 한 건에
   > 0.7~2.0초로 돌았다. L4·T4 면 그와 비슷하거나 낫다.
   > 카드 이름은 우리 코드가 보지 않는다. CUDA 12 계열이면 그대로 돈다.

4. **[스팟/선점형] 은 절대 켜지 마라.** 싸지만 구글이 아무 때나 꺼 버린다.
   시연 중에 꺼지면 끝이다.

5. **부팅 디스크** — [변경] 을 누른다.
   - 운영체제: **Deep Learning on Linux**
   - 버전: **Deep Learning VM ... CUDA 12.x ... Ubuntu 22.04** (이름에 이 셋이 다 들어간 것)
   - 디스크 종류: 균형 있는 영구 디스크(pd-balanced)
   - 크기: **100GB**

   > 왜 이 이미지인가: 그래픽카드 드라이버(NVIDIA)가 미리 깔려 있다. 맨 우분투로
   > 시작하면 드라이버 설치부터 해야 하고 그게 제일 잘 깨지는 대목이다.
   > 왜 100GB 인가: 모델 파일과 파이썬 라이브러리로 30~40GB 는 쉽게 찬다.

6. **네트워킹**
   - 네트워크 인터페이스를 펴고, **외부 IPv4 주소** 에서 1단계에 만든 **`ktest-demo-ip`** 를 고른다.
   - 네트워크 태그에 **`ktest-api`** 를 적는다. (3단계 방화벽이 이 이름을 보고 붙는다)

7. **[만들기]**. 몇 분 걸린다.
   처음 켤 때 "NVIDIA 드라이버를 설치할까요?" 를 물으면 **예** 라고 답한다.

## 3단계 — 방화벽: 8001 만 열기

**8100 은 열지 않는다.** 받아쓰기 서버는 같은 컴퓨터 안에서만 불리면 되고,
바깥에 열면 아무나 우리 모델을 쓸 수 있다. (서버 자체도 `127.0.0.1` 로만 듣게
못 박아 두었으니 이중으로 막히는 셈이다.)

1. 검색창에 **`방화벽`** → **VPC 네트워크 → 방화벽** → **[방화벽 규칙 만들기]**
2. 이렇게 채운다.
   - 이름: `allow-ktest-api-8001`
   - 트래픽 방향: **수신(ingress)**
   - 일치 시 작업: **허용**
   - 대상: **지정된 대상 태그** → 대상 태그: **`ktest-api`**
   - 소스 IPv4 범위: `0.0.0.0/0`
   - 프로토콜 및 포트: **지정된 프로토콜 및 포트** → **TCP** 체크 → 포트 **`8001`**
3. **[만들기]**

> `0.0.0.0/0` 은 "인터넷 어디서든" 이라는 뜻이다. 백엔드 서버의 주소를 정확히
> 안다면 그 주소만 적는 편이 안전하다. 모르면 이대로 열되, **반드시 `ktest.env` 의
> `KTEST_API_KEY` 를 채워 열쇠 없는 요청을 막는다.**

## 4단계 — 접속해서 차리기

1. VM 인스턴스 목록에서 `ktest-demo` 줄의 **[SSH]** 를 누른다. 브라우저에 검은 창이 뜬다.
2. 그래픽카드가 보이는지 먼저 확인한다.

   ```bash
   nvidia-smi
   ```

   표가 나오면 정상이다. `command not found` 가 나오면 드라이버 설치가 아직 안 끝난
   것이니 1~2분 뒤 다시 해 본다.

3. 저장소를 받고 차림 스크립트를 돌린다. **10~20분 걸린다**(torch 가 2GB 넘는다).

   ```bash
   sudo mkdir -p /opt/ktest
   sudo git clone --depth 1 https://github.com/ktest6/k-test.git /opt/ktest/repo
   sudo bash /opt/ktest/repo/assessment/deploy/gcp/setup.sh
   ```

   > 저장소가 비공개라 `git clone` 이 로그인을 물으면, 내 PC 에서 폴더를 압축해
   > 올린 뒤 이렇게 한다:
   > ```bash
   > sudo bash /opt/ktest/repo/assessment/deploy/gcp/setup.sh --from-tar ~/k-test.tar.gz
   > ```
   > (tar 안에 `assessment/` 폴더가 맨 위에 있어야 한다)

4. 끝나면 화면 맨 아래에 **"어댑터 준비됨? 아니오 / 열쇠 채워짐? 아니오"** 가 뜬다.
   맞다. 다음 단계에서 채운다.

## 5단계 — 어댑터와 열쇠 올리기

### 어댑터

1. SSH 창 오른쪽 위 **톱니바퀴 → 파일 업로드** 를 눌러 `v2_adapter.tar.gz` 를 올린다.
   (내 홈 폴더 `~` 에 올라간다. 크면 몇 분 걸린다)
2. 푼다.

   ```bash
   sudo tar -xzf ~/v2_adapter.tar.gz -C /opt/ktest/adapters/v2
   ls /opt/ktest/adapters/v2
   ```

3. **`adapter_config.json` 이 보여야 한다.** 안 보이고 폴더가 하나 더 있으면
   그 안의 내용을 위로 옮긴다. (8/22 에 내 PC 에서 실제로 이랬다 — 압축 안에
   `adapters/v2` 가 한 겹 더 있었다)

   ```bash
   sudo mv /opt/ktest/adapters/v2/adapters/v2/* /opt/ktest/adapters/v2/
   ```

4. 주인을 바꿔 준다.

   ```bash
   sudo chown -R ktest:ktest /opt/ktest/adapters
   ```

### 열쇠

```bash
sudo nano /opt/ktest/env/ktest.env
```

`GEMINI_API_KEY=` · `AZURE_SPEECH_KEY=` · `AZURE_SPEECH_REGION=` 뒤에 값을 붙여 넣는다.
`KTEST_API_KEY=` 에는 영문·숫자로 아무 긴 문자열이나 하나 정해 넣는다
(**같은 값을 백엔드의 `ASSESSMENT_API_KEY` 에도 넣어야 한다**).

저장은 `Ctrl+O` → `Enter`, 나가기는 `Ctrl+X`.

> 값에 따옴표를 씌우지 마라. 주석(`#`)을 값 뒤에 붙이지 마라. 그대로 값이 된다.

### 켜기

```bash
sudo systemctl restart ktest-stt ktest-api
```

받아쓰기 서버는 처음 켤 때 베이스 모델(약 1GB)을 내려받으므로 **1~2분 걸린다.**

## 7단계 — 백엔드에 알려 주기

백엔드의 `.env` 에 이 둘을 넣으라고 전한다.

```
ASSESSMENT_URL=http://<고정IP>:8001
ASSESSMENT_API_KEY=<5단계에서 정한 KTEST_API_KEY 와 같은 값>
```

이제 `cloudflared` 터널은 필요 없다. 주소가 안 바뀌므로 앞으로 매번 알려 줄 일도 없다.

### `https` 가 필요한가 — 지금은 필요 없다

백엔드 코드를 확인했다. 채점 서버를 부르는 것은 **백엔드 서버 자신**이다
(`backend/src/modules/ai/infrastructure/providers/assessment-scoring.adapter.ts`
에서 NestJS 의 HttpService(axios)로 부른다). 브라우저가 직접 부르는 것이 아니므로
"https 페이지에서 http 를 못 부른다"(혼합 콘텐츠) 문제가 생기지 않는다.
그래서 `http://<고정IP>:8001` 로 충분하다.

**다만 이런 경우에는 https 가 필요해진다:**

- 백엔드를 올린 곳(Cloud Run·Vercel 등)이 바깥으로 http 를 못 나가게 막을 때
- 프론트엔드가 채점 서버를 **직접** 부르게 될 때 (지금 설계에는 없다)
- 심사위원에게 주소를 보여 줘야 하는데 브라우저가 "안전하지 않음" 을 띄우는 게 싫을 때

그때는 Caddy 로 인증서를 자동으로 받는 것이 제일 간단하다. **도메인 이름이 하나
있어야 한다**(IP 주소로는 인증서를 못 받는다).

```bash
# 방화벽에서 80·443 도 먼저 열어야 한다 (3단계와 같은 방법, 포트만 80,443)
sudo apt-get install -y debian-keyring debian-archive-keyring apt-transport-https curl
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' \
  | sudo gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' \
  | sudo tee /etc/apt/sources.list.d/caddy-stable.list
sudo apt-get update && sudo apt-get install -y caddy

# 도메인을 이 VM 의 고정 IP 로 향하게 해 둔 뒤:
sudo tee /etc/caddy/Caddyfile > /dev/null <<'EOF'
ktest.example.com {
    reverse_proxy 127.0.0.1:8001
}
EOF
sudo systemctl restart caddy
```

이러면 `https://ktest.example.com` 이 바로 된다(인증서는 Caddy 가 알아서 받고 갱신한다).
그 뒤에는 방화벽에서 8001 을 **닫아도** 된다.

## 돈이 얼마나 드나 (대략)

**켜 두는 동안 계속 나간다.** 아래는 서울 리전 기준 어림값이고, 정확한 값은
콘솔의 **요금 계산기(Pricing Calculator)** 로 확인한다.

| 고른 것 | 하루(24시간) | 열흘(9/2까지) | 한 달 상시 |
|---|---|---|---|
| g2-standard-4 (L4 1장) | **약 17 달러** (8/25 에 확인한 값) | 약 170 달러 | 약 500 달러 |
| n1-standard-4 + T4 1장 | 약 13 달러 | 약 130 달러 | 약 390 달러 |
| 디스크 100GB | — | 약 3 달러 | 약 10 달러 |
| 고정 IP (VM 에 붙어 있을 때) | — | 거의 0 | 거의 0 |

**돈을 아끼는 법**

- **시연 전까지는 밤에 끈다.** 콘솔에서 VM 을 [중지] 하면 계산 요금이 멈춘다
  (디스크 값만 나간다). 다시 [시작] 하면 systemd 가 서버 둘을 알아서 다시 띄우고,
  고정 IP 라 **주소도 그대로다.** 백엔드에 다시 알려 줄 필요가 없다.
- **9/2 시연 전날부터 당일까지만 계속 켜 둔다.**
- 시연이 끝나면 **VM 을 삭제하고 고정 IP 예약도 해제한다.** 안 그러면 계속 나간다.
- 팀에 $300 크레딧이 있으므로 위 금액이 크레딧에서 먼저 빠진다.

## VM 에서 **처음** 돌릴 때 확인할 것 (아직 아무도 안 해 본 대목)

이 문서와 `setup.sh` 는 **리눅스 VM 이 없는 상태에서 만든 것이다.**
문법 검사와 healthcheck 동작은 확인했지만, **아래 항목은 실제 VM 에서 처음
돌려 봐야 알 수 있다.** 하나씩 짚어 가며 확인하고, 어긋나면 고쳐서 저장소에 반영한다.

- [x] **파이썬 판** (8/26 확인: deadsnakes 3.11 설치 됨. 단 librosa 1.0 은 3.12 전용이라 0.11 로 낮춤). `setup.sh` 는 3.11 이상을 찾고, 없으면 deadsnakes 에서 3.11 을 깐다.
      Deep Learning VM 에 3.10 만 있으면 이 설치가 실제로 되는지 확인.
      (`requirements.txt` 의 numpy 2.4 는 3.10 에 설치본이 없다)
- [ ] **`pip install -r requirements.txt`** 가 리눅스에서 그대로 되는지.
      지금 못 박아 둔 판들은 전부 **윈도우 파이썬 3.13** 에서 확인한 것이다.
      kiwipiepy·numpy 에서 걸릴 수 있다.
- [ ] **torch cu124 가 그 VM 의 드라이버와 맞는지.** 이미 만든 `stt-lora` VM 은
      CUDA 12.9 라 cu124 판이 그대로 돈다(드라이버가 더 새것인 건 괜찮다).
      혹시 12.4보다 낮은 이미지를 골랐다면 cu121 판으로 바꿔야 한다
      (`KTEST_TORCH_SPEC` · `KTEST_TORCH_INDEX` 환경변수로 바꿀 수 있다).
- [ ] **`ktest` 계정이 그래픽카드를 쓸 수 있는지.** root 가 아닌 계정으로 도는데
      `/dev/nvidia*` 권한이 막혀 있으면 `device = cpu` 로 나온다. healthcheck 에서 걸린다.
- [ ] **어댑터 압축 안의 폴더 겹침.** 5단계 3번 참고 — 실제로 겪은 일이다.
- [ ] **`ktest.env` 를 systemd 가 제대로 읽는지.** healthcheck 의 `llm_available`
      이 true 면 읽힌 것이다. false 면 파일 형식(따옴표·주석 위치)을 의심한다.
- [ ] **재부팅해도 저절로 뜨는지.** 콘솔에서 VM 을 [중지] → [시작] 한 뒤
      healthcheck 를 다시 돌려 확인한다. 이게 이번 이전의 핵심 이유다.
- [ ] **백엔드가 실제로 부를 수 있는지.** 백엔드 쪽에서 `POST /score` 를 한 번 태워
      쓰기 1건 · 말하기 1건이 200 으로 오는지 확인한다.
- [ ] **음성 내려받기.** 채점 서버가 Supabase 의 음성 주소를 VM 에서 내려받을 수
      있어야 한다. 막히면 말하기가 전부 실패한다.

## 문제가 생기면

| 증상 | 먼저 볼 곳 |
|---|---|
| 바깥에서 `curl` 이 안 됨 | 방화벽 규칙 · 네트워크 태그 `ktest-api` |
| `stt_available = false` | `journalctl -u ktest-stt -n 50` · 어댑터 폴더 |
| `device = cpu` | `nvidia-smi` · venv-stt 의 torch 가 cuda 판인지 |
| `llm_available = false` | `/opt/ktest/env/ktest.env` 의 `GEMINI_API_KEY` |
| 401 이 옴 | `KTEST_API_KEY` 와 백엔드 `ASSESSMENT_API_KEY` 가 같은 값인지 |
| 서버가 계속 죽었다 살아남 | `journalctl -u ktest-api -n 100` 에 진짜 원인이 있다 |
